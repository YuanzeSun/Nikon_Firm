# C1.70 RAW + 120min v3

此版修改启动内存池。后续以保持原启动内存配置的 [v4](120min_v4.md) 为准，v3 保留供对照。

固件：`firmware/Z6II_C1.70_RAW_120min_v3/Z6_2_0170.bin`，49,002,888 字节，版本 C1.70。

SHA-256：`ae38ec66372bbaf16609241a8408fe51c00160b757efbc6d7d0d820c0f288f85`。

## 修改位置

以下均为主模块运行地址，模块基址 `0x10020000`。

| 位置 | 修改 |
| --- | --- |
| `0x103c3128` | RAW 能力选择器，`01 d1` → `00 bf` |
| `0x119eb760` | 126 项时长表中的 96 个普通项：1,799,000 → 7,200,000 ms；30 个零项保留 |
| `0x1048922c` | 启动阈值：1,798,001 → 7,199,001 ms |
| `0x104a7e34` | 累计帧数阈值：215,784 → 863,784 |
| `0x104a82d4` / `0x104a82da` | 4K 59.94/50p 包计数阈值：3,596/3,749 → 14,388/15,003 |
| `0x104e20d0` | 录像初始化调用转到 `0x10040d12`，使用扩展索引布局 |
| `0x104e1adc` / `0x104e208e` / `0x104e24d2` / `0x10693634` | 索引内存参数：30 → 50 |

特殊模式的 `0x10478290 = 180000` 保留。主模块共修改 4,451 字节，完整补丁分为 126 个不重叠区域。

## 索引与新增代码

复制原模块 `[0x1053c806, 0x1053d6a8)` 到 `0x10040002`，保持四字节对齐余数，重定位 158 条 BL。录制调用使用副本；原编辑调用 `0x105385c4` 仍进入原函数。

| 地址 | 内容 |
| --- | --- |
| `0x10040002` / `0x1004069a` | MP4 / MOV 初始化副本 |
| `0x10040d12` | 外层初始化副本 |
| `0x10041000` / `0x10041100` | MOV / MP4 初始化包装函数 |
| `0x10042000` | 移动固定结构并重设索引指针 |
| `0x10043000` / `0x10043800` | 32 位 / 64 位文件偏移布局表 |

这些地址原为零填充。对应 MMU 节可执行，未落入启动 RAM 复制或清零目标。包装函数维持栈对齐及返回值，初始化成功后调整 31 个上下文指针和两个描述结构内部指针。

| 上下文字段 | 新容量 |
| --- | --- |
| `+0x230` 视频 STSZ | 864,000 × 4 字节 |
| `+0x26c` 视频 CTTS | 864,000 × 8 字节 |
| `+0x3dc` AAC STSZ | 337,836 × 4 字节 |
| `+0x3c4` 音频 STSC | 67,564 × 12 字节 |
| `+0x3f0` / `+0x404` 音频文件偏移 | 原容量四倍；窄表 67,564 × 4，宽表 144,000 × 8 字节 |
| `+0x6a8` 辅助轨 STSZ | 864,000 × 4 字节 |
| `+0x204` / `+0x3b0` / `+0x67c` STTS | 各 4,096 × 8 字节 |

保留原视频 chunk、关键帧等表容量。普通固定帧率/GOP 的 STTS 不随每帧增长。完整的字段、旧偏移、新偏移及容量在补丁 JSON 的 `layouts` 中。

单次索引分配为 `50 × 0x58800 + 0x80000 = 18,649,088` 字节。32 位布局用至偏移 16,784,732；64 位布局用至 18,030,912。

## 内存分配

录像元数据堆 `0x33` 从 11 MiB 扩到 18 MiB。原生捕获分配器计入头部和对齐后申请 18,651,136 字节，小于 18,874,368 字节堆容量。

- 动态模式 3/6：`0x10302d70` 父堆请求 57 → 64 MiB；子堆划分为 4 + 36 + 18 + 6 MiB。`0x10302e02`、`0x1030309a` 修改末尾堆偏移；两个 RAM 描述模板也同步扩容。
- 静态模式 4/5：`0x11994348`、`0x11994420` 的大小和分配单位改为 18 MiB；后续堆描述 `0x11994330`、`0x119943f0`、`0x11994408` 的基址后移 7 MiB。
- 启动登记的索引池 13 同步扩容；同堆登记总量 67,800,448 字节，小于 88 MiB。读取池 4 保持原容量。

模式 6 的父堆来自 `0x11994450`：21 个 3,459,072 字节单元。原生分配器将 64 MiB 请求取整为 20 个单元，实际占用 69,181,440 字节，剩一个单元。整机运行时其他临时分配的并发占用尚未验证。

## 续录关系

控制入口 `0x104a783e` → 关闭请求 `0x104c0f58` → 工作线程 `0x104e1b80` 仅 flush；打开下一文件时，`0x104e1830` 在 `0x104e1b18` 调用完整续录入口 `0x10522c92`。停止录制后由 `0x1053c4bc` 写出最终索引。

续录后保留累计帧数和包计数；新上下文相隔 `0x728` 字节，文件对齐字段为 `+0x4d4`。原生最多 10 个文件的限制保留。4 GiB 切分路径在高码率下可能先达到 10 段；64 位大文件路径的索引已通过离线检查。实际存储卡是否采用大文件路径需要机身确认。

## 已检查

在 Unicorn 中执行原 ARM/Thumb 指令，给编码器输出提供合成样本长度、GOP、变化的 CTS 和音频交织；文件 write/seek/flush 使用替代实现。

- MOV/MP4、32/64 位偏移四种初始化及固定结构迁移；12 组最终索引写出。
- 两小时连续索引：119.88、100、50、25 fps；变长 AAC 及约 345,561,216 个 PCM 样本。119.88 fps 共 863,137 帧，完整索引写出 12,271,616 字节，返回 0。单文件 100 fps 窄偏移只检查数组写入，其超过 4 GiB 的合成数据不作为有效单文件验证。
- 四组 MOV/MP4、窄/宽偏移配置的 10 段续录，合计 40 次最终索引写出通过。
- 126 项时长、7 档计时、5 组打包条件、模式 3/4/5/6 内存描述、18 组捕获分配请求。
- 原认证程序完整处理原包和 v3 包，各 49,002,856 字节正文，均返回 1；SHA1 使用原固件指令。模块/容器 CRC16、保存的启动数据认证后缀、XOR 编解码及独立重建一致。

尚未用相机实际录满两小时，也未验证整机同时运行编码器、存储卡和其他任务时的内存占用。

## 重建与继续修改

```powershell
python tools/build_120min_v3.py verify
python tools/build_120min_v3.py build
```

默认输出 `build/Z6II_C1.70_RAW_120min_v3/`，已存在则停止；可用 `--output` 指定新目录。只需 Python 标准库，输入均在仓库中。

`tools/patches/z6ii_170_raw_120min_v3.json` 保存每处原字节和新字节、原始/修改后主模块哈希、158 条调用重定位及四种布局。`recording_layout_v3.asm` 保存新增代码的汇编片段，按注明地址分别汇编；实际构建直接重放 JSON。继续修改时须同步补丁 JSON、模块/包哈希及构建脚本中的清单哈希。
