# C1.70 RAW + 120min v4

普通 23.976/25/29.97/50/59.94p 延长至 120 分钟，100/119.88p 和特殊模式保留原时长。HDMI RAW 补丁沿用 RAW-only。版本 C1.70，文件名 `Z6_2_0170.bin`。

固件位于 `firmware/Z6II_C1.70_RAW_120min_v4/`，大小 49,002,888 字节。

SHA-256：`6ad4cbf7866c2a79041f6b3411b2063bc88a13b2d0a3010be38f3b8da91d39a4`。

## 保留原启动内存

取消 v3 的启动池和堆扩容：

- `0x10693634`、`0x104e1adc`、`0x104e208e`、`0x104e24d2` 保留原分配参数 30。
- `0x10302d70`、`0x10302e02`、`0x1030309a` 保留原动态父堆大小及偏移；动态模板不改。
- `0x11993480–0x11994500` 内存描述表保持原字节，静态堆大小及后续堆地址不改。
- 主模块早期启动、异常向量区域和原 RAM 初始化数据保持原字节；启动池登记逐项执行结果与原版一致。

单次录像索引仍分配 `30 × 0x58800 + 0x80000 = 11,399,168` 字节。录像元数据堆仍为 11 MiB，动态父堆仍为 57 MiB。没有增加录像索引的内存申请量。

## 更新流程与验证

已定位的更新菜单、版本检查、包解析、认证和更新请求代码保持原字节。用 v4 主程序离线执行包解析，官方、RAW-only、v4 三个包均返回成功；用 v4 中的原认证指令处理完整官方包和 v4 包，均通过。

离线执行原固件指令检查了四种 MOV/MP4、32/64 位布局，25/29.97/50/59.94p 的两小时连续索引及 10 段续录，共 40 次最终索引写出；另检查了 PCM、数组末端写入、126 项时长和 7 档停止计时。100/119.88p 按原时长检查。

原最多 10 个文件的限制保留；4 GiB 切分时可能先达到段数上限。尚未实机验证 v4 的开机、更新菜单及长录。未建立脱离主固件的恢复入口。

## 重建

```powershell
python tools/build_120min_v4.py verify
python tools/build_120min_v4.py build
```

仅需 Python 标准库。脚本复用 v3 的补丁重放和容器校验函数，并增加启动内存和更新区域的原字节检查。默认输出 `build/Z6II_C1.70_RAW_120min_v4/`；输出目录已存在则停止。

主模块 SHA-256：`a95efb0078296040671dc9a7588d8dddff90ee5b754b298103cbc9df255a75d3`。84 个补丁区域，主模块共变化 4,346 字节。
