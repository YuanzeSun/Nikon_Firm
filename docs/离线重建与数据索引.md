# 离线重建与数据索引

本仓库已通过 GitHub API 确认为私有仓库。所有者要求保存后续可复用的原始数据和读取值，因此包含下列材料。数据仅来源于本次 Z6 II C1.70 分析；未证明能用于其他机型、固件或机身。

## 输入材料

| 文件 | 用途 | SHA-256 |
| --- | --- | --- |
| `inputs/official/Z6_2_0170.bin` | 未修改的官方 C1.70 原包，49,002,888 字节 | `5a9640b4c07abe1ecbf5a52655cbec6b893bba045bb2a1a1d21055b9f8f9d06d` |
| `inputs/boot/boot_auth_10000088.bin` | 从机身运行地址 `0x10000088..0x1000008f` 读取的 8 字节 | `e5c5da8e5ac52c5e99d094a4913ab7bb188547ebf7076b7a7c01bcabedbf88d0` |
| `inputs/nikon_xor_tables.json` | 3 张各 256 项的容器 XOR 解码/编码表 | `5294749bd4b3db4e7654cff20e9ce8c26138447500e656cab1ff1065d6e8a612` |

已读取的启动数据与摘要后缀：

```text
boot_bytes = ba 3d 5c 39 7b f3 31 a9
mask       = e2 2b 5d 78 7c 69 3f fe
suffix     = 58 16 01 41 07 9a 0e 57
```

重建工具必须先验证这组值能够复现官方包头的摘要；不会在缺少数据、哈希不符或原指令不符时生成升级文件。读取值是这次成功重建所用的输入，不应称作适用于所有相机的通用密钥。

## 不连接相机的重建

`tools/raw_only.py` 适用于 Python 3.10 或更高版本，只用标准库。路径按脚本所在仓库解析，可以在 Windows、WSL 或 Linux 中运行。

```powershell
# 验证仓库里已发布的升级包，不写文件
python tools/raw_only.py verify

# 从保存的原包与认证数据重建，输出目录必须不存在
python tools/raw_only.py build

# 解码原包并提取模块，供后续反汇编使用
python tools/raw_only.py extract
```

默认输出：

- `build/Z6II_C1.70_RAW_only/Z6_2_0170.bin`：重建的完整升级包。
- `build/Z6II_C1.70_RAW_only/build_report.json`：本次离线验证报告。
- `build/Z6II_C1.70_RAW_only/SHA256SUMS.txt`：重建文件哈希。
- `build/official_decoded/decoded_container.bin` 和 `modules/`：`extract` 产生的分析材料，不是独立升级包。

`build` 生成的 BIN 必须与已发布文件逐字节一致，SHA-256 为 `f3e4fa07de6a8818d4bbf1ef65cb3ee5b7954bee8a353fd9b65ca7b7e4e9b11e`。工具检查版本/目录元数据、全部模块 CRC、容器 CRC、原包/候选摘要、完整差异范围和录像时长参数。它不访问相机，也不模拟擦除、刷写或 HDMI 输出。

## 历史材料

- `archive/work/feature_scan/boot_cache_read_live.json`：启动字节读取、两处 RAM 备份/恢复、F001/F002 状态以及相机版本信息。
- `archive/work/feature_scan/service_ram_digest_check.json`：一次早期的 RAM 读取假设检查；该次读回全零，两种摘要假设均失败，`verified_authentication_bytes_obtained` 为 `false`，因此是失败记录，不应作为认证数据使用。
- `reports/rebuild_verification.json`：使用本仓库输入完成的离线重建报告，输出与发布 BIN 逐字节一致。最终摘要复现结果也可用 `tools/raw_only.py verify` 重新检查。成功读取日志里的 `read_bytes_verified_against_official_digest: false` 是读取当时尚未进行摘要验证的状态，后续构建和独立校验已通过。
- `archive/work/feature_scan/cached_read_route_emulation.json`：缓存读取路线的离线预验证。
- `archive/work/feature_scan/read_boot_via_ram_cache.py` 及依赖：原始 USB/WPD 读取脚本。会临时写 RAM；保存用于审查，本次离线复现不需要执行。
- `archive/work/feature_scan/build_authenticated_raw_only.py`：本次实际使用的原构建脚本。
- `archive/work/feature_scan/verify_*.py`、`review_raw_only_risk.py`：原始认证、RAW 路径、包解析和风险复核脚本。
- `archive/work/feature_scan/*.c`、`*.asm`：相关伪代码和反汇编；不是可编译的完整源码。
- `archive/outputs/Z6_2_0170_RAW_only_candidate/`：原构建报告、独立校验报告、完整认证机器码报告、RAW 选择路径报告和包解析报告。
- `archive/outputs/Z6_2_0170_RAW_only_risk_review/`：刷入前风险复核原件。
- `archive/outputs/Z6_2_0170_installability/`：摘要算法的机器码验证和升级路径伪代码摘录。
- `reports/user_feedback.json`：后来用户报告成功刷入的记录，单独保存，不改写历史报告。

历史脚本保留了原工作区的目录结构和绝对路径，直接执行可能需要恢复原目录并安装 NumPy、Unicorn、Capstone；WPD 脚本还依赖 Windows COM/comtypes。它们用于保留证据和后续研究。通常重建与校验请使用新的 `tools/raw_only.py`，无需这些依赖。

`archive` 中原 `SHA256SUMS.txt` 涉及当时完整输出目录，包括未重复上传的候选主模块等。它用于历史对照；整个当前仓库的上传文件清单以根目录 `SHA256SUMS.txt` 为准，发布 BIN 的哈希以其固件目录内的清单为准。

`.gitattributes` 禁用 Git 的自动行尾转换，以保持历史原件及哈希清单跨平台一致。根目录清单列出所有上传文件（清单本身除外），不包含本地 `build/` 输出。
